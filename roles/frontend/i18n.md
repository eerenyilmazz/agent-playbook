# Internationalization (i18n)

## Rules
- No user-facing text hard-coded in templates or code; all text goes through translation keys.
- Keys are descriptive and namespaced: `checkout.payment.cardDeclined`, not `text1`.
- Never build sentences by concatenating translated fragments; use placeholders: `"{{count}} items in cart"`.
- Plurals use the i18n library's plural rules (languages differ).
- Dates, numbers and currency are formatted with locale-aware formatters, never by hand.
- Store dates in UTC; display in the user's time zone.
- Layouts allow text to grow (some languages are much longer than English).
- Support right-to-left if any target language needs it; plan it early.
- `lang` attribute on the page matches the current language.

## Turkish-specific
- Case conversion uses locale-aware functions (`toLocaleUpperCase('tr')`) because of i/İ and ı/I.
- Sorting uses a locale-aware collator.

## Process
- Missing translations fail the build or are clearly logged; never show raw keys in production.
